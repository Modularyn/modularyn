# G-02 control map

[g02-foundation.json](g02-foundation.json) maps each control of the [G-02 foundation threat model](../threat-models/g02-foundation.md), the 60 `TM-G02` controls in [controls.json](../threat-models/controls.json), to the automated tests that evidence it and to the named residual risks that remain when it works as built. SEC-08 wrote it with the adversarial suite of AC-003 and AC-004, and it carries the residual risks of SEC-02 to SEC-09 for the operator's acceptance at the G-02 qualification review.

The map records where evidence is, not that a gate is qualified. The threat model stays a planning contract, and requirement state stays in the [coverage register](../../coverage/register.json); nothing here changes a state, a gate or an owner. Evidence records for the tests that run in CI are the evidence plan's ([g02-plan.json](../../evidence/g02-plan.json)).

## Format

| Field | Meaning |
|---|---|
| `entries` | One entry per `TM-G02` control, in the model's order |
| `entries[].tests` | The tests that evidence the control: each a test project and the fully qualified name of a declared `[Fact]` or `[Theory]` method of it |
| `entries[].residuals` | The residual risks that name the control, in order |
| `residuals[]` | Each residual: its statement, the controls and security orders it concerns, who owns closing it, the tests that state it where it is tested, its sources (repository files or record identifiers), and its acceptance, `pending` until the operator accepts it |

[ControlMapTests](../../../tests/Modularyn.Repository.Tests/ControlMapTests.cs) refuses a map that leaves a control with neither evidence nor a residual, names a control twice or out of order, cites a test that is not a declared test method of its project and class, lists residuals on an entry that do not name its control, names an unknown control or order, cites a source that does not exist, or leaves a residual out of this README; and it requires every security order from SEC-02 to SEC-09 to state at least one residual.

## Method

A cited test is one that fails when the control's guard is removed. For the guards SEC-08's own tests cover, that was checked by removal: the guard was broken, the test was seen to fail, and the guard was restored. Every cited test runs in CI, in the unit job or, with the trait `Requires=PostgreSQL`, in the real-provider job against PostgreSQL 18, where the AC-003-N02 browser case runs Chrome Headless Shell from an archive whose SHA-256 is pinned in [.github/browsers.json](../../../.github/browsers.json) and checked before extraction. The adversarial cases compose the real tenant directory, identity, authorization, audit, settings, features, Files and the filesystem provider; nothing in them is a test double of a security seam.

Where a control is only partly evidenced, the part that is not is a residual, so an entry with both tests and residuals is a control whose remaining part is stated rather than claimed. A residual that a test states, such as the direct-database residual of sealed references, cites that test.

## Decisions for the operator

**The seal and its row's payload and kind (`RR-G02-030`).** A sealed propagated reference is bound to its row's identity and its store's purpose, not to the row's payload, kind or state. SEC-08 tested and states the residual rather than binding them, because binding changes every store's capture. AC-004-N03 shows that a direct database writer who requeues a job, rewrites its payload or changes its kind gets a run in the producer's revalidated tenant and within its current authority only, which a revocation then stops. The options are:

1. Accept the residual as stated, within the trust the threat model already gives database administrators (as for audit integrity, `RR-G02-029`).
2. Bind the seal to a digest of the payload and kind as well. Every store's capture and its tests change (the outbox, the inbox, jobs, schedules and Files' recovery), stored references of the current format stop opening, and a row whose payload is redacted after it completes must keep its digest. A dispatcher's own state changes stay unbound, so requeueing a row remains possible.
3. Bind the seal to the payload and kind and record each run's attempt in the sealed content, so a row runs once per capture. Replay protection then needs a store-side record of consumed captures, which a database writer can also reset.

The Reviewer judged the first option acceptable for G-02, a direct database writer being already outside the model's trust boundary, and asked that the residual be revisited when payloads gain external effects (`RR-G02-041`). The acceptance remains the operator's, and is pending.

**A secret reference's name.** Decided and built: `secret:<name>` is a secret form, so the log scrubber redacts it, the audit store and durable payloads refuse it, and Settings' display redaction agrees ([SecretForms.cs](../../../src/Framework/Modularyn.Framework.Observability/SecretForms.cs); `TM_G02_047_A_secret_reference_is_masked_in_telemetry_as_settings_mask_it_while_configuration_still_binds_it`). The secret store's refusals, at startup or later, name no secret either: each gives its reason and asks the operator to compare the mounted secret directory with the configuration's secret references, and a refusal logged through the framework carries no name (`TM_G02_047_A_refused_resolution_logged_through_the_framework_carries_no_secret_name`).

**A service identity acting for a user.** Built, not a residual: a service identity now acts for a user only in that user's propagated work. A member context resolved from claims that server code built gives it no subject (`MAZ009`).

## Residual risks for acceptance

Each residual remains when its controls work as built. The operator accepts each at the G-02 qualification review, or names the order that closes it.

- `RR-G02-001` **Trusted deployers and load-time module code.** Someone who can change packages or deployment configuration can defeat in-process controls (TH-G02-001, TH-G02-069). The deployment lock detects drift from the reviewed release, but module assemblies load before it is verified, so code that runs at load time is not stopped, and the lock binds manifests and listed files only, not the host's own assemblies. Controls: `TM-G02-001`, `TM-G02-011`. Orders: SEC-02. Owner: OPS-009 and DEV-018 at G-08.
- `RR-G02-002` **Composition switches and module disabling.** Composition switches are not recorded in or checked against the lock (FND-001), and disabling a module with a report of its dependents, running work and retained data (FND-003) is not built. Under the restart model a selection that drops a required module is refused at composition. Controls: `TM-G02-001`, `TM-G02-002`. Orders: SEC-02. Owner: No G-02 work order; DEV-005 tooling at G-06.
- `RR-G02-003` **Host, container and recovery evidence.** The evidence for these controls runs in test hosts over real PostgreSQL and the filesystem provider. Evidence on the sample host and its container, including lifecycle, migration, key-ring and audit recovery, is CODE-10's and is not part of this map. Controls: `TM-G02-003`, `TM-G02-017`, `TM-G02-026`, `TM-G02-032`, `TM-G02-046`, `TM-G02-048`, `TM-G02-050`, `TM-G02-051`, `TM-G02-053`, `TM-G02-054`, `TM-G02-060`. Orders: SEC-02, SEC-03, SEC-04, SEC-06, SEC-07. Owner: CODE-10 on CI-01.
- `RR-G02-004` **Extension properties are not built.** No extension-property mechanism exists, so there is nothing for TM-G02-005 to govern and no test evidences it. A module that adds extension properties must arrive with their sensitivity and permission declarations and the tests of this control. Controls: `TM-G02-005`. Orders: SEC-02. Owner: No G-02 work order (FND-005).
- `RR-G02-005` **Request-time limits and declared-field paging.** Request size, structure and header limits are enforced and tested, but whole-request time limits, JSON field lengths, and bounded paging, sorting and filtering on declared fields are partly built and not evidenced. The fixture endpoints bound their own pages. Controls: `TM-G02-009`, `TM-G02-021`, `TM-G02-029`. Orders: SEC-02, SEC-04, SEC-05. Owner: CODE-06 with CODE-03.
- `RR-G02-006` **Refusals before the application pipeline.** The host-filtering 400 for an unconfigured host and Kestrel's own refusals, such as 431, come before the application pipeline: they carry no problem body, no HSTS and no nosniff header, and a host without UseModularynApi answers ingress refusals with bare status codes. AC-004-N01 observes the bare 400, which reveals nothing. Controls: `TM-G02-006`, `TM-G02-010`, `TM-G02-060`. Orders: SEC-02, SEC-09, SEC-08. Owner: No owner named.
- `RR-G02-007` **Secrets in module code and release artifacts.** Secret types keep secrets out of what the framework formats and logs, but cannot stop module code from logging a revealed value or placing one in an exception. That a secret setting accepts only replacement is not evidenced, and release artifacts are not scanned for secrets. The repository itself is scanned by CI's secret-scan check, gitleaks over the full history on every pull request and every push to main, but no cited test evidences that scan. Controls: `TM-G02-047`. Orders: SEC-02, SEC-07. Owner: CODE-04; OPS-004 at G-08.
- `RR-G02-008` **Provider compatibility and settings reload.** Typed configuration is validated before readiness, but provider compatibility, such as the PostgreSQL server version, is checked only by the test harness, and validation before an application or tenant settings reload takes effect is not built; deployment options take effect only at restart. Controls: `TM-G02-048`. Orders: SEC-02. Owner: CODE-03 and CODE-04.
- `RR-G02-009` **Key ring at rest and key-management policy.** The data-protection key ring is stored unencrypted in an owner-only directory, whose access control is its only protection. Application code can still register another key manager, add escrow sinks or turn off rotation after the declaration, the declaration keeps one store per options scope without removing them, and the separate backup of the ring is an untested operational procedure. Controls: `TM-G02-050`. Orders: SEC-02. Owner: No G-02 work order; backup procedure at G-08.
- `RR-G02-010` **HSTS choices are not recorded with the release.** HTTPS redirection and HSTS are emitted and tested, but the deployment's subdomain and preload choices are not recorded with the release. Controls: `TM-G02-060`. Orders: SEC-02. Owner: No G-02 work order.
- `RR-G02-011` **Shared capacity and within-tenant availability.** G-02 has no per-tenant quotas: request bounds and quota reservation limit single requests and one tenant's temporary storage, not its share of the host (TH-G02-070). Within a tenant, one member can hold every read slot or pending upload place. TenantCache has no size bound. Its shared factory starts on the thread pool, so the factory deadline releases every waiter even of a factory that blocks its thread synchronously; but a factory that ignores its token keeps running after its waiters are released, and holds its pool thread for as long as it blocks it, until the factory's own bound ends it, so a dependency that stalls and ignores cancellation can hold one abandoned call per key for each deadline that passes. Cache outage behaviour (AC-030) is outside G-02. Controls: `TM-G02-009`, `TM-G02-034`, `TM-G02-045`. Orders: SEC-02, SEC-04, SEC-06. Owner: OPS-018 resource governance at G-08.
- `RR-G02-012` **Weak passwords.** Adaptive hashing raises the cost of guessing a stolen verifier but cannot protect a password that is easy to guess (TH-G02-072). Controls: `TM-G02-055`. Orders: SEC-03. Owner: Accepted at G-02 qualification.
- `RR-G02-013` **Throttling and sign-in availability.** Delays and source blocking keep an attacker from locking an account indefinitely, but several sources acting together keep a targeted user's sign-in slowed for as long as they fail (TH-G02-076), and no operator alert exists. A reverse proxy that is not declared collapses its clients into one source, timing uniformity was measured on loopback only, and throttle rows accumulate until retention removes them. Controls: `TM-G02-015`. Orders: SEC-03. Owner: No G-02 work order for an operator alert.
- `RR-G02-014` **Key separation for seeds and passkeys.** Encrypted one-time-password seeds and integrity-tagged passkey records stay protected only while their keys are held apart from the database; a compromise that reaches both exposes them (TH-G02-073, TH-G02-075). Controls: `TM-G02-056`, `TM-G02-058`. Orders: SEC-03. Owner: Accepted at G-02 qualification; restore evidence with CODE-10 and OPS-004.
- `RR-G02-015` **Credential journeys are G-03's.** G-02 delivers the stored forms of one-time-password seeds, recovery codes and passkey records with their tests. Enrolment, verification, recovery and passkey registration and sign-in, and the limits on those codes at an entry point, are G-03's journeys. Controls: `TM-G02-015`, `TM-G02-056`, `TM-G02-057`, `TM-G02-058`. Orders: SEC-03. Owner: G-03.
- `RR-G02-016` **Administrator-issued delegation and impersonation.** Delegation that the subject grants is built and tested; delegation or impersonation issued by an administrator is specified by no G-02 work order and is not built. Its existing evidence is ExecutionPrincipal's separation of actor and effective subject, with identity kind, which every decision and audit record uses; G-03 must build the journey on it. Controls: `TM-G02-018`. Orders: SEC-05, SEC-03. Owner: G-03.
- `RR-G02-017` **Client credential providers.** The origin-bound credential provider is built and tested; generated and dynamic clients that ask it for every request and refuse redirects off its origin are not driven end to end, and no upload can be client-visible until clients model an upload's body. Controls: `TM-G02-013`. Orders: SEC-03, SEC-09. Owner: CODE-06; G-03 for token issuance.
- `RR-G02-018` **Freshness window.** Within the declared freshness bound a revoked grant or session can still act (TH-G02-020, TH-G02-040): under the bounded profile another process sees a change only within the bound. Security-sensitive permissions are decided at the current profile. Controls: `TM-G02-017`, `TM-G02-033`. Orders: SEC-05. Owner: Accepted at G-02 qualification.
- `RR-G02-019` **Module code is trusted in process.** Module code runs in process with the host's authority. Code that opens the connection itself can run any SQL past every filter, reflection can build the adapter's markers and internal constructors, and owner-bound rules rest on a source check. Server code that builds a session-scheme claims principal can establish a member context for any member; since SEC-08 it gives a service identity no authority there. A handler that casts the request's IHttpResponseFeature to IHttpResponseBodyFeature, which is the server's own object, writes a response of any media type past the media-type check that every supported write path passes. The query guard depends on EF Core 10.0.14's query shapes. Controls: `TM-G02-004`, `TM-G02-011`, `TM-G02-025`, `TM-G02-028`, `TM-G02-029`, `TM-G02-030`. Orders: SEC-03, SEC-04, SEC-05, SEC-08. Owner: None: the module trust model; every EF Core upgrade reruns the query-guard tests.
- `RR-G02-020` **What a host operation reached.** The framework audits each host scope's grant, with its actor, operation and reason, and each cross-tenant read with its entity and grant, before the access. Which tenants an operation affected is recorded only if the operation's module records it, as the AC-004-N03 fixture does. Including tenant navigations from a host scope is untested, and a tenant's invalidation does not reach host-scope entries that aggregate it, which their staleness bound limits. Controls: `TM-G02-028`, `TM-G02-033`. Orders: SEC-04, SEC-08. Owner: No owner named.
- `RR-G02-021` **The principal inside authorized work.** AuthorizedWorkRunner decides for the principal its caller passes, but the work runs in a new scope whose principal accessor holds nothing, so module code that resolves the accessor there sees no principal and is refused. The Authorization README states that a step must pass the principal it was given; what remains is that the runner does not set the accessor, so code that relies on it fails closed rather than acting. Controls: `TM-G02-019`, `TM-G02-023`. Orders: SEC-05. Owner: No owner named.
- `RR-G02-022` **Member invitations are G-03's.** Tenant administrators cannot add members until G-03's invitation flow; memberships change only through identity's audited host operations, and G-03 must lead from a tenant-level decision to that write without implicit host scope. Controls: `TM-G02-025`, `TM-G02-028`. Orders: SEC-05. Owner: G-03.
- `RR-G02-023` **Entitlements and plans are G-03's.** Permissions, settings, features and composition are kept separate and tested; entitlements and plans do not exist until G-03, where they attach at the feature gate. Controls: `TM-G02-024`. Orders: SEC-05. Owner: G-03.
- `RR-G02-024` **Data at rest.** Content encryption under FND-031 is not enabled, so file content, records and audit rows are stored unencrypted, and the slice relies on host and database access controls: a host or database compromise exposes Confidential and Restricted data. Controls: `TM-G02-043`, `TM-G02-046`, `TM-G02-052`. Orders: SEC-06. Owner: A later work order (FND-031), as the operator decided.
- `RR-G02-025` **Scanner limits.** Files has no content scanner: release runs the deployment's policy, and the opt-in allowlist policy makes no file safe, since a released document can still carry an exploit or script. Detection recognizes known patterns, so novel content can pass (TH-G02-049). Controls: `TM-G02-042`. Orders: SEC-06, SEC-09. Owner: Accepted at G-02 qualification; each deployment's release policy.
- `RR-G02-026` **Already delivered data.** Revocation stops new access through the gateway but cannot recall files or responses already delivered. Controls: `TM-G02-044`. Orders: SEC-06. Owner: Accepted at G-02 qualification.
- `RR-G02-027` **No anonymous file delivery.** Every download needs a signed-in session, as the operator decided for G-02; the bounded-bearer profile for public files is gate W's. Controls: `TM-G02-044`. Orders: SEC-06. Owner: Gate W.
- `RR-G02-028` **Files edge cases.** Under invariant globalization a file name is checked as given, without normalization; active grants per tenant are not capped; one spare-bits token case is not exercised by its test; and scheduled recovery waits on the job runtime. Controls: `TM-G02-043`, `TM-G02-044`, `TM-G02-045`. Orders: SEC-06. Owner: No owner named; CODE-05 for scheduled recovery.
- `RR-G02-029` **Audit integrity.** Append-only is enforced by the persistence adapter, not by the database, so a database administrator or the schema owner can alter or delete audit rows, and no tamper evidence is claimed (TH-G02-060). Controls: `TM-G02-051`, `TM-G02-052`. Orders: SEC-07. Owner: Accepted at G-02 qualification.
- `RR-G02-030` **A sealed reference does not bind its row's payload, kind or state.** The seal binds a stored reference to its row's identity and its store's purpose. A writer with direct database access can therefore requeue a row, or change its payload or kind, and it runs again under the same reference. AC-004-N03 shows each such run stays in the producer's revalidated tenant and within its current authority, and stops once that authority is revoked. The Reviewer judged stating it acceptable for G-02, since a direct database writer is already outside the model's trust boundary, as RR-G02-029 accepts for audit rows, and asked that it be revisited when payloads gain external effects (RR-G02-041). Controls: `TM-G02-027`, `TM-G02-039`, `TM-G02-041`. Orders: SEC-07, SEC-08. Owner: The operator's decision (see the control map README).
- `RR-G02-031` **Scrubber and payload rule limits.** The scrubber and the payload rule recognize secret forms, now including a secret reference, behind the allowlisted-fields rule; a password or a secret's value that a module logs or places in a payload has no recognizable form and is not caught. Nothing yet runs quarantined-payload redaction or receipt pruning on its own. Controls: `TM-G02-036`, `TM-G02-039`, `TM-G02-053`. Orders: SEC-07. Owner: No owner named; a maintenance runner later.
- `RR-G02-032` **No operator endpoints for audit, diagnostics and lag.** Audit and diagnostics reads are authorized and tested as services, but no HTTP endpoint exposes them, and durable work's lag is not exposed to operators. Controls: `TM-G02-037`, `TM-G02-052`, `TM-G02-054`. Orders: SEC-07. Owner: A later API order under CODE-06's inventory.
- `RR-G02-033` **Access records precede the access.** Records of access, such as a host-scope grant, a filter bypass or an audit read, are written in their own transaction before the access, so a record can exist for an access that then failed; a soft-deleted read in a named deployment scope is not recorded. Controls: `TM-G02-029`, `TM-G02-051`. Orders: SEC-07. Owner: Accepted design.
- `RR-G02-034` **Durable work needs the declared key ring.** A host must declare SEC-02's key ring for any durable work, or no reference is stored and work defers; references of format 1 are no longer read, which is safe only because nothing has been released. Controls: `TM-G02-027`, `TM-G02-050`. Orders: SEC-07. Owner: Deployment requirement.
- `RR-G02-035` **Correlation without the API conventions.** A host without UseModularynApi decides correlation after the ingress and so adopts no declared proxy's trace context. Controls: `TM-G02-053`. Orders: SEC-07. Owner: Documented limitation.
- `RR-G02-036` **Composition roots outside the samples.** DEP014 gives sample hosts a composition-root role, and DEP015 refuses references between test projects; a composition-root role for applications built on Modularyn outside the samples is left to a later order. Controls: `TM-G02-004`. Orders: SEC-09. Owner: A later work order, as the operator decided.
- `RR-G02-037` **Sign-in posts JSON.** Identity's sign-in endpoint accepts JSON only, so a sample's sign-in page posts with a small same-origin script that fetches its antiforgery token, not with a plain HTML form. Controls: `TM-G02-007`. Orders: SEC-09. Owner: No owner named.
- `RR-G02-038` **Evidence on fixture endpoints rather than every shipped surface.** Safe methods that change nothing, strict input contracts, conflict responses and browser cross-site behaviour are evidenced on the fixture modules' declared endpoints, through a verified browser, not on every shipped endpoint or the sample's pages; no G-02 interface renders permission-dependent controls, and the AC-002 and AC-012 acceptance families have no tests here. Controls: `TM-G02-007`, `TM-G02-008`, `TM-G02-016`, `TM-G02-019`, `TM-G02-023`, `TM-G02-030`, `TM-G02-059`. Orders: SEC-02, SEC-03, SEC-05. Owner: CODE-06 and CODE-09; the AC-002 and AC-012 families outside the G-02 plan.
- `RR-G02-039` **Contract evolution against the previous release.** Breaking changes are detected against the committed baseline; no comparison with the previous release's contract, consumer migration gate or detection of meaning-only changes exists. Controls: `TM-G02-012`. Orders: no security order. Owner: CODE-06.
- `RR-G02-040` **No tenant-configurable declaration for settings.** Deployment options are separate from settings and cannot be overridden by a tenant, which AC-003-N03 shows; but a setting has no declaration that it is tenant-configurable, so a tenant holding the management permission can override any declared setting. Controls: `TM-G02-049`. Orders: SEC-02. Owner: A later settings work order, which must add a tenant-configurable declaration to setting definitions and refuse a tenant's override of any setting that lacks it.
- `RR-G02-041` **Idempotent external effects from events.** Consumers deduplicate and order delivery, and API mutations take idempotency keys; no G-02 event handler performs an external effect, so idempotency keys for such effects are unevidenced. Controls: `TM-G02-036`. Orders: no security order. Owner: The first module with an external effect.
- `RR-G02-042` **Client-visible values have no audience.** A value is client-visible to every member of its tenant or to none. A value visible only to an administrator is a user-scope override, as AC-004-B02 prepares it, or a value served through an authorized endpoint. Controls: `TM-G02-014`. Orders: SEC-08. Owner: No owner named.
- `RR-G02-043` **Return addresses may name any configured origin.** Sign-in accepts a local path or any configured public origin as its return address, another tenant's domain included; the request that follows is resolved and refused there like any other, and no Host or forwarded value is ever used. Controls: `TM-G02-006`. Orders: SEC-08. Owner: Accepted design.
- `RR-G02-044` **Test browser and package provenance.** The pinned Chrome Headless Shell archives' SHA-256 values rest on Playwright's CDN and Google serving identical bytes, since neither publishes a hash, and their third-party licenses were not reviewed one by one. dotnet nuget verify --all verified Microsoft.Playwright 1.64.1's Microsoft author signature and nuget.org repository countersignature, with their timestamps, without error. It failed only System.ComponentModel.Annotations 5.0.0, signed in 2020: both signatures' validity periods have expired (NU3037), and the local trust store explicitly distrusts both timestamps' Symantec chain (NU3028). Restore still gates both packages on the lock's content hashes, and both packages match nuget.org's catalog SHA-512. Controls: none; it supports evidence. Orders: SEC-08. Owner: No owner named; supports AC-003-N02.
- `RR-G02-045` **Personal data has no recognized form.** Personal data outside the recognized secret forms is not recognized by redaction or by the payload rule; only producers' choice of references keeps it out, and a per-kind privacy classification needs a manifest or contract change. Controls: `TM-G02-039`, `TM-G02-053`. Orders: SEC-07. Owner: A later manifest or contract change.

## What the map does not show

A cited test shows its control working where the test exercises it; it does not show that the control is complete everywhere, which the residuals state where it is not. Evidence on the sample host and its container is CODE-10's (`RR-G02-003`). The website profile's controls, `TM-W`, are gate W's and are not mapped here.
