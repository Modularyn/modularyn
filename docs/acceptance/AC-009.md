## AC-009-B01 — Enforce declared file size and cancellation boundaries

- Family: `AC-009`
- Type: `boundary`
- Profiles: `reference`
- Requirements: `FND-030`, `FND-031`
- Layers: `real-provider-integration`, `api-contract`
- Security dependencies: `AC-003`, `AC-004`, `AC-031`

### Profile scope

- `reference`: G-02 filesystem Files byte/metadata integrity, immutable versions, size/cancellation boundaries, interrupted writes and restore. Eligibility and access outcomes are prerequisites from the security families.

### Preconditions

- The upload fixture configures a supported 1,024-byte maximum. Inputs contain 1,023, 1,024 and 1,025 bytes; a fourth upload can pause before finalization.

### Steps

1. Complete each size variant and compare metadata.
2. Cancel the fourth upload before finalization and inspect temporary and authoritative storage.

### Expected outcome

- The first two sizes complete; 1,025 bytes reports the declared size limit without a completed version.
- The canceled upload has a visible canceled disposition and no authoritative partial version.

### Evidence to retain

- Configured limit, per-size outcomes, cancellation trace and storage/version inventories.

## AC-009-B02 — Check the content-package media size edge

- Family: `AC-009`
- Type: `boundary`
- Profiles: `website`
- Requirements: `FND-030`, `MOD-014`, `CMS-009`
- Layers: `real-provider-integration`, `api-contract`
- Security dependencies: `AC-003`, `AC-004`, `AC-031`

### Profile scope

- `website`: W upload/import through filesystem Files, versioned editorial metadata, package-byte integrity, interrupted storage and restore. Scanning/quarantine, denied access and revocation are supplied by AC-003 and AC-031.

### Preconditions

- Three otherwise valid eligible image fixtures have exact sizes of 10 MiB minus one byte, 10 MiB and 10 MiB plus one byte; manifest sizes and hashes match. Deployment capacity supports the contract limit.

### Steps

1. Dry-run each package and apply only the two supported-size plans through Files.

### Expected outcome

- The first two sizes pass the format size check and retain exact stored lengths.
- The final size is rejected as over the package media limit before apply.

### Evidence to retain

- Byte counts and digests, dry-run diagnostics and stored version sizes.

### Preconditions

- asset-1 has a complete version; a new upload declares the digest of fixture A while carrying different fixture B bytes.

### Steps

1. Attempt to complete the mismatched upload.

## AC-009-P02 — Keep imported and uploaded media versions reproducible

- Family: `AC-009`
- Type: `positive`

- Requirements: `FND-030`, `MOD-014`, `CMS-009`
- Layers: `real-provider-integration`, `api-contract`

### Profile scope

- `website`: W upload/import through filesystem Files, versioned editorial metadata, package-byte integrity, interrupted storage and restore. Scanning/quarantine, denied access and revocation are supplied by AC-003 and AC-031.

### Preconditions

- The minimal content-package image and its exact hash/size form one fixture. A second eligible image version and descriptive alt text are prepared under the same logical asset.

1. Import the first version through Files, then upload the second.
2. Read each version by its identity and inspect its dimensions, media type, alt text and byte digest.

- Editorial placement resolves the selected asset version.

## AC-009-R01 — Reconcile interrupted filesystem writes and restore versions

- Family: `AC-009`
- Type: `recovery`
- Profiles: `reference`
- Requirements: `FND-030`, `FND-031`, `MOD-014`
- Layers: `real-provider-integration`, `operational-recovery`
- Security dependencies: `AC-003`, `AC-004`, `AC-031`

### Profile scope

- `reference`: G-02 filesystem Files byte/metadata integrity, immutable versions, size/cancellation boundaries, interrupted writes and restore. Eligibility and access outcomes are prerequisites from the security families.

### Preconditions

- asset-1 has two complete versions with captured digests in a coordinated backup. A third upload can stop midstream or after bytes are staged but before metadata commit.

### Steps

1. Interrupt at each point in independent runs, restart storage handling and reconcile the operation identity.
2. Restore the backed-up metadata and bytes into the recovery fixture and read both historical versions.

### Expected outcome

- No partial upload becomes a completed version; retry or cleanup accounts for staged bytes without deleting referenced versions.
- Restored versions match the backup's identities, lengths and digests.

### Evidence to retain

- Fault-point traces, staged-object reconciliation report, backup identity and restored read-back digests.

## AC-009-R02 — Recover imported media after a filesystem interruption

- Family: `AC-009`
- Type: `recovery`
- Profiles: `website`
- Requirements: `FND-030`, `MOD-014`, `CMS-009`
- Layers: `real-provider-integration`, `operational-recovery`
- Security dependencies: `AC-003`, `AC-004`, `AC-031`

### Profile scope

- `website`: W upload/import through filesystem Files, versioned editorial metadata, package-byte integrity, interrupted storage and restore. Scanning/quarantine, denied access and revocation are supplied by AC-003 and AC-031.

### Preconditions

- A reviewed import stages new media while a prior publication retains old versions; the database/Files backup identifies all historical references.

### Steps

1. Stop storage midwrite, then separately after staging before database commit.
2. Reconcile each import by its original operation identity, complete or clean its unreferenced staging, and restore the coordinated backup into the recovery fixture.

### Expected outcome

- Each interrupted import reaches a reported final disposition without a dangling completed media reference.
- The restored active and historical manifests resolve to the original version hashes.

### Evidence to retain

- Import recovery reports, staged/committed inventories and restored manifest-to-media integrity results.
