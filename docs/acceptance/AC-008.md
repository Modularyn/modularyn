## AC-008-B01 — Respect compatibility and cancellation boundaries

- Family: `AC-008`
- Type: `boundary`
- Profiles: `reference`
- Requirements: `FND-027`, `FND-028`
- Layers: `api-contract`
- Security dependencies: `AC-002`, `AC-003`, `AC-004`

### Profile scope

- `reference`: G-02 advertised .NET and TypeScript client modes, public version/error contracts and cancellation. Authentication and access decisions are supplied by AC-002 and AC-003.

### Preconditions

- The release declares its oldest supported API contract and current contract. A controlled update can pause before commit or after commit before response.

### Steps

1. Read through the oldest supported and current versions, then the immediately unsupported predecessor.
2. Cancel one update before commit and cancel another after commit but before its response; query each operation's authoritative status.

### Expected outcome

- Supported versions preserve their declared fields; the unsupported version reports a compatibility failure.
- Precommit cancellation leaves no change; postcommit cancellation does not claim rollback and reports the committed outcome through reconciliation.

### Evidence to retain

- Compatibility declaration, version transcripts, cancellation timing and authoritative operation-state reads.

## AC-008-B02 — Check W client version and cancellation edges

- Family: `AC-008`
- Type: `boundary`
- Profiles: `website`
- Requirements: `FND-027`, `FND-028`
- Layers: `api-contract`, `ui`
- Security dependencies: `AC-002`, `AC-003`, `AC-004`

### Profile scope

- `website`: Only W minimal Admin and Razor delivery API contracts: typed errors, compatibility and cancellation; no GraphQL or broader client-surface claim.

### Preconditions

- The W release advertises current and oldest-supported endpoint versions; a draft save can pause either side of its database commit.

### Steps

1. Read through both supported versions and the first unsupported predecessor.
2. Cancel one save before commit and another after commit before response, then inspect operation status.

### Expected outcome

- Supported clients retain the declared revision fields and unsupported versions fail explicitly.
- Cancellation before commit preserves the old draft; cancellation after commit is reconciled as committed rather than silently retried as a new save.

### Evidence to retain

- Version matrix, cancellation traces and draft/operation state for both fault points.

## AC-008-N01 — Return actionable typed contract failures

- Family: `AC-008`
- Type: `negative`
- Profiles: `reference`
- Requirements: `FND-027`, `FND-028`
- Layers: `api-contract`
- Security dependencies: `AC-002`, `AC-003`, `AC-004`

### Profile scope

- `reference`: G-02 advertised .NET and TypeScript client modes, public version/error contracts and cancellation. Authentication and access decisions are supplied by AC-002 and AC-003.

### Preconditions

- A title field is required; a known stale token and an unsupported API version are prepared. Dynamic discovery is exercised only if advertised.

### Steps

1. Submit a missing title, then a stale write, then an unsupported API version from every advertised client.
2. For dynamic clients, separately make discovery unavailable and supply an unresolvable endpoint binding.

### Expected outcome

- Validation, concurrency and version failures retain distinct stable codes and correlation identifiers without a successful write.
- Advertised dynamic clients distinguish discovery failure from endpoint-resolution failure.

### Evidence to retain

- Input/error matrix, typed client exceptions or results, and unchanged record versions.

## AC-008-R01 — Recover a client after an interrupted response

- Family: `AC-008`
- Type: `recovery`
- Profiles: `reference`
- Requirements: `FND-028`
- Layers: `api-contract`, `real-provider-integration`, `operational-recovery`
- Security dependencies: `AC-002`, `AC-003`, `AC-004`

### Profile scope

- `reference`: G-02 advertised .NET and TypeScript client modes, public version/error contracts and cancellation. Authentication and access decisions are supplied by AC-002 and AC-003.

### Preconditions

- An idempotent create operation uses operation-1 and has committed item-2; the response is interrupted. Each advertised client mode gets an independent fixture.

### Steps

1. Reconnect, inspect operation-1 and retry using the same operation identity under the endpoint's declared contract.
2. Read the created item and compare versions.

### Expected outcome

- The client recovers the committed result without creating a second item.
- A new correlation for the retry retains linkage to operation-1 and its single final disposition.

### Evidence to retain

- Interrupted request, reconciliation/retry transcript and item/operation counts.

## AC-008-R02 — Recover the Admin after losing a save response

- Family: `AC-008`
- Type: `recovery`
- Profiles: `website`
- Requirements: `FND-028`
- Layers: `api-contract`, `ui`, `real-provider-integration`, `operational-recovery`
- Security dependencies: `AC-002`, `AC-003`, `AC-004`

### Profile scope

- `website`: Only W minimal Admin and Razor delivery API contracts: typed errors, compatibility and cancellation; no GraphQL or broader client-surface claim.

### Preconditions

- Admin has article-1 open and save operation-2 is accepted; its response is interrupted after commit.

### Steps

1. Reconnect and resolve operation-2, then reload the returned revision.
2. Retry only under the same operation identity if the endpoint requires retry.

### Expected outcome

- The UI displays the committed revision and clears its uncertain-save state.
- The history contains one revision for operation-2 and no duplicate save effect.

### Evidence to retain

- Browser state transitions, operation lookup/retry transcript and revision history.
