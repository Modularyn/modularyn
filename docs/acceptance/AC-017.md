Planning cases; see [corpus conventions](README.md). These are not execution results.

## AC-017-B01 — Resolve competing activations at one schedule instant

- Family: `AC-017`
- Type: `boundary`
- Profiles: `website`
- Requirements: `CMS-005`, `ARC-009`
- Layers: `real-provider-integration`, `api-contract`, `ui`
- Security dependencies: `AC-003`, `AC-004`, `AC-012`

### Profile scope

- `website`: W immutable publication manifests, scheduled activation, withdrawal/rollback, unique routes and cache convergence on one site/culture; search propagation is excluded.

### Preconditions

- Two validated releases target the same site/culture at 2026-11-01T12:00:00Z and expect the same active-manifest token.

### Steps

1. Read before the due instant, then let both jobs attempt activation at that instant.
2. Read repeatedly during activation and cache convergence.

### Expected outcome

- No release activates early.
- One concurrency-checked activation wins; the other has an explicit conflict. Requests never combine the two manifests, and cache convergence refers to the winning generation.

### Evidence to retain

- Schedule and expected-version inputs, competing commit outcomes and response/cache generation timeline.

## AC-017-N01 — Reject competing route owners without replacing publication

### Profile scope

- `website`: W immutable publication manifests, scheduled activation, withdrawal/rollback, unique routes and cache convergence on one site/culture; search propagation is excluded.

### Preconditions

- manifest-1 is active. A proposed release gives two different entries the canonical route /guide; another depends on an absent retained asset version.

### Steps

1. Validate and attempt activation of each proposed release.

### Expected outcome

- Neither failed release replaces manifest-1 or changes its route table.

### Evidence to retain

## AC-017-P01 — Publish a frozen manifest and later withdraw it

- Family: `AC-017`
- Type: `positive`
- Profiles: `website`
- Requirements: `CMS-004`, `CMS-005`, `CMS-007`, `ARC-009`
- Layers: `real-provider-integration`, `api-contract`, `ui`
- Security dependencies: `AC-003`, `AC-004`, `AC-012`

### Profile scope

- `website`: W immutable publication manifests, scheduled activation, withdrawal/rollback, unique routes and cache convergence on one site/culture; search propagation is excluded.

### Preconditions

- manifest-1 is active. manifest-2 binds article-1 revision-2, page-1 revision-1, exact asset versions and unique route/navigation metadata.

### Steps

1. Activate manifest-2 and read both routes, including a request spanning activation.
2. Draft article-1 revision-3, then withdraw the published release and inspect authoritative delivery and convergence status.

### Expected outcome

- Each request resolves one consistent manifest and the later draft does not mutate manifest-2.
- Withdrawal has an explicit recorded state and delivery follows it; immutable manifests and their revision history remain retained.

### Evidence to retain

- Manifest hashes, active-pointer/withdrawal history, per-request manifest identities and propagation status.

## AC-017-R01 — Roll back after failed activation and interrupted propagation

- Family: `AC-017`
- Type: `recovery`
- Profiles: `website`
- Requirements: `CMS-004`, `CMS-005`, `CMS-009`, `ARC-009`
- Layers: `real-provider-integration`, `api-contract`, `operational-recovery`
- Security dependencies: `AC-003`, `AC-004`, `AC-012`

### Profile scope

- `website`: W immutable publication manifests, scheduled activation, withdrawal/rollback, unique routes and cache convergence on one site/culture; search propagation is excluded.

### Preconditions

- manifest-1 and its compatible schemas/renderers/media are retained. manifest-2 is validated; cache propagation can pause after an authoritative switch.

### Steps

1. First inject a failure before the activation commit and inspect the pointer.
2. In a separate run activate manifest-2, interrupt cache propagation, restart the consumer, then explicitly roll back to validated manifest-1.

### Expected outcome

- Precommit activation failure leaves manifest-1 active.
- Restart and rollback converge caches to the selected authoritative manifest with visible pending/failed/completed status; no historical manifest is edited.

### Evidence to retain

- Fault traces, immutable manifest hashes, rollback transaction and cache convergence observations.
