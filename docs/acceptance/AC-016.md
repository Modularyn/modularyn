Planning cases; see [corpus conventions](README.md). These are not execution results.

## AC-016-B01 — Keep schema and preview versions pinned at an edit boundary

- Family: `AC-016`
- Type: `boundary`
- Profiles: `website`
- Requirements: `CMS-001`, `CMS-004`, `CMS-006`
- Layers: `real-provider-integration`, `api-contract`, `ui`
- Security dependencies: `AC-003`, `AC-004`, `AC-012`, `AC-031`

### Profile scope

- `website`: W versioned content types, fields and references, typed composition, revision conflicts and exact-revision preview. Preview authorization is supplied by AC-003.

### Preconditions

- article-1 revision-1 uses schema version 1. A compatible schema version 2 adds an optional summary field while both renderers remain installed.

### Steps

1. Save revision-2 against schema version 2 with the summary absent.
2. Open preview explicitly for revision-1, save revision-3, and refresh that preview.
3. Propose a narrowing schema change against existing values.

### Expected outcome

- Absence of the optional summary is preserved and historical revision-1 retains schema version 1.
- The selected preview still renders revision-1; narrowing reports affected content for a migration decision rather than discarding values.

### Evidence to retain

- Schema versions, stored field snapshots, preview revision identities and incompatibility report.

## AC-016-N01 — Reject invalid fields, references and stale authoring

- Family: `AC-016`
- Type: `negative`
- Profiles: `website`
- Requirements: `CMS-001`, `CMS-002`, `CMS-003`, `CMS-004`
- Layers: `real-provider-integration`, `api-contract`, `ui`
- Security dependencies: `AC-003`, `AC-004`, `AC-012`, `AC-031`

### Profile scope

- `website`: W versioned content types, fields and references, typed composition, revision conflicts and exact-revision preview. Preview authorization is supplied by AC-003.

### Preconditions

- article-1 has a current version; two authors opened the preceding version. The valid type and renderer fixtures are retained.

### Steps

1. Independently submit a missing required title, an integer title, a missing content reference and an unavailable block version.
2. Save from author A, then submit author B's stale token.

### Expected outcome

- Each invalid draft reports its field/reference/dependency diagnostic.
- The stale write produces a visible conflict; none of the rejected inputs silently replaces the current valid revision.

### Evidence to retain

- Invalid-input matrix, diagnostics, conflict display and retained revision hashes.

## AC-016-P01 — Save and preview a precisely selected composed revision

- Family: `AC-016`
- Type: `positive`
- Profiles: `website`
- Requirements: `CMS-001`, `CMS-002`, `CMS-003`, `CMS-004`, `CMS-006`
- Layers: `real-provider-integration`, `api-contract`, `ui`
- Security dependencies: `AC-003`, `AC-004`, `AC-012`, `AC-031`

### Profile scope

- `website`: W versioned content types, fields and references, typed composition, revision conflicts and exact-revision preview. Preview authorization is supplied by AC-003.

### Preconditions

- The article type version 1 has required title and a content reference to page-1. Installed version-1 block, layout and template renderers support a heading and paragraph.

### Steps

1. Create article-1 using the reference and two ordered typed blocks; save revision-1.
2. Change its paragraph and save revision-2.
3. Preview revision-1 and compare both revisions.

### Expected outcome

- Each revision retains its schema and renderer dependencies, field values and block order.
- Preview shows revision-1 exactly and comparison identifies the paragraph change without changing production publication.

### Evidence to retain

- Typed revisions and dependency identities, comparison output and preview-selected revision observations.

## AC-016-P02 — Preserve typed taxonomy references during authoring

- Family: `AC-016`
- Type: `positive`
- Profiles: `website`
- Requirements: `CMS-002`, `CMS-004`, `CMS-010`
- Layers: `real-provider-integration`, `api-contract`, `ui`
- Security dependencies: `AC-003`, `AC-004`, `AC-012`, `AC-031`

### Profile scope

- `website`: W versioned content types, fields and references, typed composition, revision conflicts and exact-revision preview. Preview authorization is supplied by AC-003.

### Preconditions

- Taxonomy garden has parent term crops and child term herbs. The article type declares a term reference targeting garden; both terms have stable identities.

### Steps

1. Save article-1 revision-1 referencing herbs.
2. Change the display label of herbs, save article-1 as revision-2 and compare the typed references in both revisions.

### Expected outcome

- The term reference resolves within garden and its parent relationship remains crops.
- The label edit does not replace the term identity; both article revisions retain the same stable reference while their own revision identities remain distinct.

### Evidence to retain

- Taxonomy identities and parent graph, stored field references and article revision comparison.

## AC-016-R01 — Recover an interrupted save and restore an older revision as a draft

- Family: `AC-016`
- Type: `recovery`
- Profiles: `website`
- Requirements: `CMS-001`, `CMS-004`
- Layers: `real-provider-integration`, `api-contract`, `ui`, `operational-recovery`
- Security dependencies: `AC-003`, `AC-004`, `AC-012`, `AC-031`

### Profile scope

- `website`: W versioned content types, fields and references, typed composition, revision conflicts and exact-revision preview. Preview authorization is supplied by AC-003.

### Preconditions

- article-1 has revisions 1 and 2; an autosave operation-3 can lose its response after commit.

### Steps

1. Interrupt the response and reconnect using operation-3's status.
2. Restore revision-1 as a new draft, validate it against its supported schema and compare history.

### Expected outcome

- Reconciliation identifies exactly one saved revision for operation-3.
- Restore creates a distinct validated draft; it does not overwrite revisions 1 or 2 or activate a publication.

### Evidence to retain

- Autosave/reconnect history, operation identity, revision comparison and publication pointer before/after.
