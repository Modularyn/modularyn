## AC-019-B01 — Apply declared navigation and redirect limits

- Family: `AC-019`
- Type: `boundary`
- Profiles: `website`
- Requirements: `MOD-009`, `CMS-012`, `UI-009`
- Layers: `real-provider-integration`, `api-contract`, `ui`
- Security dependencies: `AC-003`, `AC-004`, `AC-012`, `AC-031`

### Profile scope

- `website`: W blog, pinned Git documentation, taxonomy/navigation, SEO/redirects and contact journeys; one site/culture and no engagement, search or newsletters.

### Preconditions

- Version-1 packages contain valid navigation trees of depth 16 and 17 and redirect chains of length 16 and 17, each ending at a real route.

### Steps

1. Dry-run each independent variant.
2. Publish the valid variants and follow their final navigation target and redirect chain; also inspect the configured query-discard behavior.

### Expected outcome

- Depth/length 16 validates and resolves the declared target; 17 is rejected before apply.
- Redirect resolution follows the configured same-site status/target rules and drops incoming query data as the package contract declares.

### Evidence to retain

- Exact trees/chains, boundary diagnostics and redirect/navigation request transcripts.

## AC-019-P01 — Read a blog post through taxonomy and ordered navigation

- `website`: W blog, pinned Git documentation, taxonomy/navigation, SEO/redirects and contact journeys; one site/culture and no engagement, search or newsletters.

## AC-019-P02 — Read two documentation versions and submit contact

- Family: `AC-019`
- Type: `positive`
- Profiles: `website`
- Requirements: `MOD-011`, `CMS-017`
- Layers: `real-provider-integration`, `api-contract`, `ui`
- Security dependencies: `AC-003`, `AC-004`, `AC-012`, `AC-031`

### Profile scope

- `website`: W blog, pinned Git documentation, taxonomy/navigation, SEO/redirects and contact journeys; one site/culture and no engagement, search or newsletters.

### Preconditions

- Two documentation versions use distinct entry keys/routes and pinned commits from a locally available configured repository binding. A contact page uses a prequalified named destination.

### Steps

2. Follow the contact route, submit a valid request and inspect its durable receipt and delivery status.

## AC-019-R01 — Recover an interrupted documentation and navigation import

- Family: `AC-019`
- Type: `recovery`
- Profiles: `website`
- Requirements: `MOD-009`, `MOD-011`, `UI-009`
- Layers: `real-provider-integration`, `ui`, `operational-recovery`
- Security dependencies: `AC-003`, `AC-004`, `AC-012`, `AC-031`

### Profile scope

- `website`: W blog, pinned Git documentation, taxonomy/navigation, SEO/redirects and contact journeys; one site/culture and no engagement, search or newsletters.

### Preconditions

- Version v1 documentation and ordered navigation are published. A reviewed package introduces v2 with distinct entry keys and revised navigation; its snapshots are already local.

### Steps

1. Interrupt apply before database commit, then reconcile and resume using the original operation identity.
2. Validate and publish the completed result, retaining v1.

### Expected outcome

- The interruption preserves the prior published graph.
- Recovery introduces v2 and its navigation once, retains v1 identities/routes and reports every mapped item's outcome.

### Evidence to retain

- Import checkpoints/result, stable-key mappings and browser reads of both documentation versions.
