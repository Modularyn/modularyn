Planning cases; see [corpus conventions](README.md). These are not execution results.

## AC-023-B01 — Inspect theme reflow, contrast and keyboard alternatives

- Family: `AC-023`
- Type: `boundary`
- Profiles: `website`
- Requirements: `UI-005`, `UI-007`, `UI-008`, `UI-011`, `UI-012`, `UI-014`, `OPS-019`
- Layers: `ui`
- Security dependencies: `AC-002`, `AC-003`, `AC-004`, `AC-031`

### Profile scope

- `website`: W minimal React/TypeScript Admin action ledger and original Razor theme, with keyboard, focus, assistive technology, contrast, responsive/error states and WCAG 2.2 AA evidence. Account and authority actions are supplied by security families.

### Preconditions

- The declared W pages and Admin dialogs include the longest valid titles, populated validation messages and nested navigation. The test covers each advertised viewport/browser pairing.

### Steps

1. Inspect at 320 CSS pixels wide, 200 percent text size and 400 percent zoom using the applicable WCAG conditions.
2. Measure normal text, large text, controls and focus contrast; inspect target sizes and applicable exceptions.
3. Reorder blocks and navigation without dragging, traverse dialogs and return focus to their triggers.

### Expected outcome

- Content and actions remain usable without unintended loss or two-dimensional scrolling where reflow applies.
- Text and controls meet applicable 4.5:1 or 3:1 contrast criteria; focus/target-size findings are assessed against WCAG 2.2 AA.
- Keyboard alternatives preserve order and dialog focus returns predictably.

### Evidence to retain

- Viewport/zoom captures, contrast measurements, criterion/exception decisions and keyboard ordering/focus results.

## AC-023-N01 — Present validation and conflict failures accessibly

- Family: `AC-023`
- Type: `negative`
- Profiles: `website`
- Requirements: `UI-002`, `UI-005`, `UI-007`, `UI-008`, `UI-012`, `OPS-019`
- Layers: `ui`
- Security dependencies: `AC-002`, `AC-003`, `AC-004`, `AC-031`

### Profile scope

- `website`: W minimal React/TypeScript Admin action ledger and original Razor theme, with keyboard, focus, assistive technology, contrast, responsive/error states and WCAG 2.2 AA evidence. Account and authority actions are supplied by security families.

### Preconditions

- The authoring form has a required title; a contact message is required; a stale draft token and conflicting route are available.

### Steps

1. Use only the keyboard to submit each invalid author/contact form, stale save and route collision.
2. Inspect error summaries, field associations, status announcements and focus, then correct each input.

### Expected outcome

- Each failed operation is explained in text and programmatically associated with the affected input or action.
- Entered data is retained, focus reaches the relevant error without a trap, and corrected submissions can complete.

### Evidence to retain

- Four error-state workflows, field/summary associations, focus sequence and assistive-technology observations.

## AC-023-P01 — Complete the minimal action ledger and public journeys accessibly

- Family: `AC-023`
- Type: `positive`
- Profiles: `website`
- Requirements: `UI-002`, `UI-005`, `UI-007`, `UI-008`, `UI-009`, `UI-011`, `UI-012`, `UI-014`, `OPS-019`
- Layers: `ui`
- Security dependencies: `AC-002`, `AC-003`, `AC-004`, `AC-031`

### Profile scope

- `website`: W minimal React/TypeScript Admin action ledger and original Razor theme, with keyboard, focus, assistive technology, contrast, responsive/error states and WCAG 2.2 AA evidence. Account and authority actions are supplied by security families.

### Preconditions

- The W action ledger lists authoring, validation/conflicts, preview, schedule/publish/rollback, media, taxonomy/navigation, routes, contact delivery, import review and recovery. The original theme and each advertised browser/assistive-technology pairing are identified.

### Steps

1. Using keyboard and screen reader, author and compare a revision, inspect validation, resolve a prepared conflict and open its exact preview.
2. Schedule, publish and roll back a release; upload/select versioned media and edit taxonomy/navigation and routes.
3. Inspect contact delivery, review and apply an import plan, and inspect a recovery operation through their declared Admin routes.
4. On the public site, navigate home, blog listing/post, documentation versions and the contact form; submit a valid contact request.

### Expected outcome

- Every listed action has a reachable declared route, usable accessible name/role/state and visible focus, with the expected domain outcome.
- The ledger reports each action and browser/assistive-technology pairing separately; no missing action is counted as native completion.

### Evidence to retain

- Action-by-action ledger with route, inputs and outcomes.
- Keyboard/focus traces, screen-reader observations and a criterion-level WCAG 2.2 AA assessment including manual findings.

## AC-023-R01 — Recover an interrupted editor without losing work or focus

- Family: `AC-023`
- Type: `recovery`
- Profiles: `website`
- Requirements: `UI-002`, `UI-005`, `UI-008`, `UI-012`
- Layers: `ui`, `api-contract`, `operational-recovery`
- Security dependencies: `AC-002`, `AC-003`, `AC-004`, `AC-031`

### Profile scope

- `website`: W minimal React/TypeScript Admin action ledger and original Razor theme, with keyboard, focus, assistive technology, contrast, responsive/error states and WCAG 2.2 AA evidence. Account and authority actions are supplied by security families.

### Preconditions

- An author has an unsaved paragraph and focused Save control; one save fixture fails before commit and another commits but loses its response.

### Steps

1. Interrupt each save and reconnect.
2. Resolve the recorded operation outcome, restore retained unsaved input where needed and complete the save.
3. Close any recovery dialog and continue editing by keyboard.

### Expected outcome

- The UI distinguishes unsaved changes from an uncertain committed operation and announces recovery status.
- Recovery preserves text, avoids duplicate revisions and restores usable focus; the next edit remains possible.

### Evidence to retain

- Input snapshots, operation/revision counts, announced state transitions and focus trace.
