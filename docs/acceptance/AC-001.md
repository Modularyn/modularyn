## AC-001-B01 — Check the inclusive compatibility edges

- Family: `AC-001`
- Type: `boundary`
- Profiles: `reference`
- Requirements: `FND-001`
- Layers: `unit`, `real-provider-integration`
- Security dependencies: `AC-031`

### Profile scope

- `reference`: G-02 module graph and lifecycle on the reference modular monolith, with PostgreSQL and filesystem providers. Trust qualification is supplied by AC-031.

### Preconditions

- A declares support for B versions from 2.0.0 through 2.2.0 inclusive; equivalent fixtures exist at 1.9.9 and 2.2.1.

### Steps

1. Compose each of B 1.9.9, 2.0.0, 2.2.0 and 2.2.1 with A, keeping runtime and provider pins fixed.

### Expected outcome

- Only 2.0.0 and 2.2.0 satisfy the declared range; each rejected version identifies the same unsatisfied constraint.

### Evidence to retain

- Four resolved-selection reports and the declared compatibility range.

## AC-001-B02 — Distinguish aliases from additional sites

- Family: `AC-001`
- Type: `boundary`
- Profiles: `website`
- Requirements: `FND-003`, `DEV-004`, `DEV-005`
- Layers: `unit`, `real-provider-integration`
- Security dependencies: `AC-004`, `AC-031`

### Profile scope

- `website`: W module composition on one tenant, site and culture; installed Razor renderers, PostgreSQL and filesystem Files only.

### Preconditions

- One site and one culture are configured; two alias bindings have already been qualified by AC-004 and AC-031.

### Steps

1. Compose once with no aliases and once with both qualified aliases.

- The second-site selection is rejected as outside W.

### Evidence to retain

- Resolved site counts and capability reports for the three selections.

## AC-001-N01 — Reject missing, cyclic and incompatible dependencies

- Profiles: `reference`
- Requirements: `ARC-001`, `FND-001`, `FND-003`
- Layers: `unit`, `real-provider-integration`

### Profile scope

### Preconditions

- Retain the valid A-to-B-to-C graph and its provider inventory as the control fixture.

### Steps

## AC-001-P01 — Activate a valid dependency graph

- Family: `AC-001`
- Type: `positive`
- Profiles: `reference`
- Requirements: `ARC-001`, `ARC-002`, `FND-002`
- Layers: `unit`, `real-provider-integration`
- Security dependencies: `AC-031`

### Profile scope

- `reference`: G-02 module graph and lifecycle on the reference modular monolith, with PostgreSQL and filesystem providers. Trust qualification is supplied by AC-031.

### Preconditions

- Module A depends on B; B depends on C; C has no dependencies. All three declare compatible runtime and provider versions.

### Steps

1. Compose A, B and C in reverse discovery order.
2. Start the application and inspect initialization, readiness and shutdown order.

### Expected outcome

- Dependencies initialize before dependents, each once; all selected modules become ready.
- Shutdown reverses the declared dependency order and completes the recorded lifecycle.

### Evidence to retain

- Resolved graph and version inventory.
- Ordered lifecycle trace and readiness observations on host and container.

## AC-001-R01 — Recover an interrupted module initialization

- Family: `AC-001`
- Type: `recovery`
- Profiles: `reference`
- Requirements: `ARC-002`, `FND-002`, `FND-003`
- Layers: `unit`, `real-provider-integration`
- Security dependencies: `AC-031`

### Profile scope

- `reference`: G-02 module graph and lifecycle on the reference modular monolith, with PostgreSQL and filesystem providers. Trust qualification is supplied by AC-031.

### Preconditions

- C initializes successfully; B has a fault injected after initialization starts but before readiness. A has not started.

### Steps

1. Start the graph and trigger the B fault.
2. Inspect completed cleanup, remove the fault and restart with the identical module selection.

### Expected outcome

- The first start reports B failed and A unavailable; cleanup identifies every initialized component.
- The second start reaches readiness without duplicate initialization effects or an active remnant from the failed start.

### Evidence to retain

- Failed and recovered lifecycle traces, cleanup inventory and durable initialization-effect counts.

## AC-001-R02 — Retry composition after restoring a renderer

- Family: `AC-001`
- Type: `recovery`
- Profiles: `website`
- Requirements: `FND-003`, `DEV-005`
- Layers: `unit`, `real-provider-integration`
- Security dependencies: `AC-031`

### Profile scope

- `website`: W module composition on one tenant, site and culture; installed Razor renderers, PostgreSQL and filesystem Files only.

### Preconditions

- The page template dependency is absent; the site has a previously usable compatible composition.

### Steps

1. Attempt to activate the incomplete selection.
2. Restore the exact declared renderer version through deployment configuration and repeat preflight and activation.

### Expected outcome

- The failed selection never becomes active.
- Revalidation resolves the restored renderer and activates the complete selection once.

### Evidence to retain

- Missing-renderer diagnostic, corrected dependency inventory and activation trace.
